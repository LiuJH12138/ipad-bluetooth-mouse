### 本次双设备真机记录

两根 USB 线同时连接。Windows 原生窗口在 iPad（iPad8,11）上收到 1608 × 1206 的画面，三点核对最大偏差为 0.7 个采样像素。初次切换时，旧采集组件尚未退出，新窗口报告 USB 正被占用。修复后，旧进程正常退出，iPhone（iPhone12,8）随后收到 750 × 1334 的画面。

- **USB 和蓝牙目标不一致。** 手机最初尚未连到电脑蓝牙。两个蓝牙候选均报告移动已送达，手机投屏持续产生新帧，但指定位置未出现指针。控制台拒绝绑定，保持仅预览。
- **两台 USB、三个蓝牙候选。** 用户将 SE 也连到电脑蓝牙后，SE 的三个落点最大偏差为 0.5 个采样像素，iPad 为 0.7。控制台为两台投屏设备分别选中了不同的蓝牙接收者。全程仅移动指针。
- **Windows 重新识别 USB 设备。** 系统切换投屏模式时，观察到两根线仍插着，设备却会短暂离开 USB 列表。控制台撤销旧绑定。为此增加了回归测试，回到原设备须用新画面重新确认上次的接收者。USB 模式未切换时单独给出重试与插线提示。

**最终完整切换通过。** 使用正式产品入口，三台蓝牙候选同时在线，从 iPad 切到 SE，再切回原 iPad。首站 iPad 的解码帧序号为 1，SE 为 231，切回 iPad 后为 314。两个不同的蓝牙接收者各自通过三点检查，切回后服务确认目标与原 iPad 一致，手动控制与助手授权均已释放。原生验收程序退出码为 0。

多轮连续切换中也遇到 USB 父设备可见、采集组件暂时读不到型号或无法打开接口的情况。控制台保留错误提示并停止输入。重新插线后曾恢复采集。此项记录保留实际设备和驱动的限制。

### 如何理解延迟

在本机控制页面通过蓝牙发送鼠标位移和滚轮操作，从发出指令开始，每约 8 毫秒取一次解码画面的像素样本，记录首次检测到变化的时间。这个数值包括蓝牙输入、iPad 响应、USB 回传和浏览器解码，不含物理鼠标采样和显示器最终出光。设置页主要是静止内容，所测帧率只代表该场景。缺少同条件的旧版样本，无法据此计算相对提速。

新版测试验证了真实鼠标输入与 USB 画面的闭环。键盘打字由用户在之前的同一蓝牙输入通道上验证。上表的 JPEG 帧年龄来自原窗口共享方案，其刷新频率与实时预览独立。

早期窗口缩略图无法捕获投屏内容，原生嵌入程序也曾被 Windows 安全软件阻止。两个原型都已移除。该版本也支持浏览器窗口共享。当前预览版通过 USB 读取视频流。

图像帧年龄仅表示进入本机服务后的经过时间，不能代替端到端视频延迟测量。其他 Windows、iPadOS、蓝牙芯片和投屏版本需要另行验证。
