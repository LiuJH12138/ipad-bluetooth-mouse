## 1.3.0 静止画面与 Computer Use 实测

2026-11-18 在同一台 Windows 电脑和 iPad 上，旧采集组件退出时记录了 `No USB media received for 15 seconds`。当时控制台仍显示蓝牙鼠标与键盘已连接。

换用修复后的采集组件，USB 投屏静置超过 45 秒，同一采集进程仍在运行。以下两次点击均由 Computer Use 在控制台的 USB 投屏画面上发起，依据 iPad 回传的页面内容核对。

| 模式 | 点选前 | 目标 | 点选后 |
| --- | --- | --- | --- |
| 普通窗口 | 设置中的「通知」 | 左栏「通用」 | 左栏选中「通用」，右侧显示「关于本机」「软件更新」等项目 |
| 全屏 | 「通用」 | 右栏「键盘」 | 页面标题变为「键盘」，出现「自动改正」「快捷键」等选项 |

切换全屏和两次操作期间沿用同一 USB 采集进程。

随后将 MSI 安装到本机的 `E:\ipad`。重新插线并解锁后，安装版在普通窗口从「键盘」切到「控制中心」，全屏从「控制中心」切到「显示与亮度」。16:12:56 到 16:16:30 是同一 USB 采集进程，全程超过三分钟。实测只打开设置页面。

环境：Windows 11、PowerShell 5.1、Node.js 26、Chrome、支持 BLE 外设角色的蓝牙适配器；iPadOS 17.6.1。

### 如何理解延迟

在本机控制页面通过蓝牙发送鼠标位移和滚轮操作，从发出指令开始，每约 8 毫秒取一次解码画面的像素样本，记录首次检测到变化的时间。这个数值包括蓝牙输入、iPad 响应、USB 回传和浏览器解码，不含物理鼠标采样和显示器最终出光。设置页主要是静止内容，所测帧率只代表该场景。缺少同条件的旧版样本，无法据此计算相对提速。

新版测试验证了真实鼠标输入与 USB 画面的闭环。键盘打字由用户在之前的同一蓝牙输入通道上验证。上表的 JPEG 帧年龄来自原窗口共享方案，其刷新频率与实时预览独立。

早期窗口缩略图无法捕获投屏内容，原生嵌入程序也曾被 Windows 安全软件阻止。两个原型都已移除。当前 USB 直连直接读取视频流，浏览器窗口共享仍可按需选择。

图像帧年龄仅表示进入本机服务后的经过时间，不能代替端到端视频延迟测量。其他 Windows、iPadOS、蓝牙芯片和投屏版本需要另行验证。

### 2026-11-18 画面操控键盘复测

在 Windows 原生窗口中开启「画面操控」，让 USB 预览获得键盘焦点。在未捕获鼠标的情况下，向 WebView2 发送四个数字键和退格键。iPad 设置搜索框的 USB 回传画面依次显示空白、`4286`、`428`，最后恢复为空。回归测试也覆盖了鼠标点击后立即打字、按住修饰键时点按，以及焦点离开画面时释放按键。

同一台 iPad 上，助手命令 `move` 能移动圆形指针，`type 7319` 能在设置搜索框输入完整数字。绝对坐标点击打开了「通用」。单独执行助手的相对鼠标 `click` 未观察到目标页面打开。对设置侧栏双向滚动后，回传画面中的列表项目位置未变；助手命令与画面操控的滚轮均未通过本次实测。

### 2026-11-18 键鼠捕获左键复测

在「开始键鼠控制」中，把 iPad 圆形指针定位到设置搜索的「取消」。修复前，WebView2 记录到左键按下与松开，USB 画面上的搜索框和软键盘依然展开。修复后，在同一台 iPad 上通过三点验证，进入键鼠捕获，由窗口的鼠标移动事件瞄准同一个「取消」，再向窗口发送左键按下与松开。回传画面显示搜索结束、软键盘收起，控制台仍显示「键鼠控制中」。这次对照仅验证捕获模式的左键。
